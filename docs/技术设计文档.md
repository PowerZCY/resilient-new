# GitHub仓库可视化动画平台 - 技术设计文档

## 技术栈选择

### 前端
- **框架**: Next.js 14+ (App Router)
- **类型系统**: TypeScript
- **样式**: Tailwind CSS + shadcn/ui
- **图标**: Lucide React
- **状态管理**: React Context + SWR/React Query
- **可视化库**: D3.js (2D可视化) + Three.js (3D效果)
- **国际化**: next-intl + JSON配置文件

### 后端
- **API路由**: Next.js API Routes
- **数据库**: PostgreSQL
- **ORM**: Prisma
- **认证**: NextAuth.js
- **缓存**: Redis (可选)

### 开发工具
- **包管理**: pnpm
- **代码规范**: ESLint + Prettier
- **测试**: Jest + React Testing Library
- **CI/CD**: GitHub Actions

## 系统架构

### 客户端架构
- 基于React组件的模块化设计
- 服务端组件(RSC)用于数据获取和SEO优化
- 客户端组件用于交互和动画渲染
- 使用SWR进行数据缓存和重新验证

### 服务端架构
- Next.js API Routes处理API请求
- 使用中间件进行认证和请求验证
- Prisma连接PostgreSQL数据库
- 实现GitHub API代理以保护用户令牌

### 数据流
1. 用户通过NextAuth.js完成GitHub OAuth认证
2. 前端通过API Routes请求数据
3. 服务端代理请求GitHub API并缓存结果
4. 处理后的数据返回给前端
5. 前端使用可视化库渲染动画

## 数据模型

### 用户模型
```typescript
model User {
  id            String    @id @default(cuid())
  name          String?
  email         String?   @unique
  image         String?
  githubId      String    @unique
  accessToken   String?
  refreshToken  String?
  tokenExpires  DateTime?
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt
  visualizations Visualization[]
}
```

### 可视化配置模型
```typescript
model Visualization {
  id            String    @id @default(cuid())
  name          String
  repositoryName String
  repositoryOwner String
  settings      Json
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt
  userId        String
  user          User      @relation(fields: [userId], references: [id], onDelete: Cascade)
}
```

### 缓存模型
```typescript
model CachedData {
  id            String    @id @default(cuid())
  key           String    @unique
  data          Json
  expiresAt     DateTime
  createdAt     DateTime  @default(now())
}
```

## API设计

### 认证API
- `POST /api/auth/[...nextauth]` - NextAuth.js处理的认证端点

### 仓库API
- `GET /api/repositories` - 获取用户仓库列表
- `GET /api/repositories/:owner/:repo` - 获取特定仓库详情
- `GET /api/repositories/:owner/:repo/commits` - 获取仓库提交历史
- `GET /api/repositories/:owner/:repo/structure` - 获取仓库文件结构

### 可视化API
- `POST /api/visualizations` - 创建新的可视化配置
- `GET /api/visualizations` - 获取用户的可视化列表
- `GET /api/visualizations/:id` - 获取特定可视化配置
- `PUT /api/visualizations/:id` - 更新可视化配置
- `DELETE /api/visualizations/:id` - 删除可视化配置

### 导出API
- `POST /api/export/video` - 导出可视化为视频
- `POST /api/export/share` - 创建分享链接

## 技术挑战与解决方案

### 挑战1：处理大型仓库数据
**解决方案**：
- 实现增量数据加载
- 服务端分页和过滤
- 数据压缩和优化传输格式
- 实现数据缓存策略

**解决方案**：
- 使用WebGL加速渲染
- 实现细节层次(LOD)系统
- 优化动画帧率

### 挑战3：GitHub API限制
**解决方案**：
- 实现智能缓存策略
- 批量请求优化
- 后台数据预取
- 用户友好的限制处理

### 挑战4：多设备支持
**解决方案**：
- 响应式设计
- 设备特定优化
- 降级渲染策略
- 触摸友好的交互设计
